# 01 · 原项目功能审计

审计对象：<https://github.com/omroy07/AgriTech>，上游 commit `a50b4332263b9bede5426f67b9bb0ca60e50bb1d`（分支 `main`，拉取日期 2026-10-25）。
线上参照：<https://agri-tech-6rs5.vercel.app/>（首页与 `/marketplace.html`）。
本地化分支：`localization/zh-cn`，基线标签 `upstream-baseline`。

## 一、仓库结构结论

上游是一个「多套应用混放」的仓库，**不是**单一前端：

| 位置 | 性质 | 是否接入主站 |
| --- | --- | --- |
| 根目录 `*.html`（约 80 个） | 线上 Vercel 使用的静态站（首页、商城、气象、社区、资讯、政策等） | 是 |
| `app.py` + `backend/` | Flask 主后端，含 API v1、模型版本、Celery、Socket.IO 等 | 是（本次精简为可运行核心） |
| `src/frontend/` | 另一套前端（README 所述） | 否，与线上页面不同源 |
| `crop_recommendation/` | 作物推荐 Flask 蓝图 + RF 模型 | 是（`/crop/`） |
| `Crop Yield Prediction/crop_yield_app/` | 独立 Flask 应用 + XGBoost 权重 | 否，独立实验模块 |
| `Fertiliser Recommendation System/` | Streamlit 应用（且存在 `.crop_type` 语法错误） | 否 |
| `Community/`、`Forum/`、`Gov_schemes/`、`Plant Disease Detection/` 等 | 各实验目录 | 部分接入 |

## 三、确认的上游缺陷（已修复或已明确标注）

1. `translations.js` 文件尾部有重复且截断的 JSON 片段 → 整站 `translations is not defined`。
2. `app.py` 启动强制要求 `GEMINI_API_KEY`，缺 Key 直接 `raise ValueError` 拒绝启动。
3. `backend/models/__init__.py` 导入 `vendor_profile`（文件不存在）、`ledger.TransactionType` 重复枚举、`traceability` 缺 `Optional` 导入 → 应用无法导入。
4. `backend/utils/validation.py` 的 `sanitize_input` 只有 1 个参数，但认证路由按 2 个参数调用 → 注册/登录 500。
5. `backend/services/auth_service.py` 缩进错误导致 `IndentationError`。
6. `crop_recommendation/routes.py` 用相对 CWD 加载模型 → 从项目根启动时找不到模型。
7. `crop_recommendation/templates/result.html` 使用 `url_for('download_report')` → 提交推荐时 500。
8. `disease.js` 的 `simulateAIAnalysis` 被注释 → 点击分析必然 `ReferenceError`。
9. `chat.html` 的 CSP `font-src https://cdnjs.cloudflare.com` → 本地图标字体被浏览器拦截，页面出现大量方框图标。
10. `weather-banner.js` 硬编码第三方天气 API Key（安全风险）。
11. `contact.html` 运行时请求 GitHub API → 国内网络必然失败并报错。
12. `community_forum.html` 请求未实现的 `/api/v1/forum/*` → JSON 解析错误。
13. `blog.html` / `faq.html` / `levelup.html` / `scheme.html` 存在 DOM 空指针异常。
