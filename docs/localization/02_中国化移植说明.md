# 02 · 中国化移植说明

## 一、语言与国际化机制整合

### 1.1 上游现状

仓库内同时存在 **5 套** 国际化实现，互相覆盖且默认英文：

| 文件 | 机制 | 问题 |
| --- | --- | --- |
| `translations.js` | `window.translations` + `data-i18n` | 文件尾部有重复且截断的 JSON 片段，解析失败 → 全站 `translations is not defined` |
| `scripts/i18n.js` | 5 语言字典 + `data-i18n` + 服务端翻译接口 | 默认 `en`，依赖 Google 翻译接口 |
| `javascript/i18n.js` | `locales/{lang}.json` + `data-i18n` | 仅 3 个语言文件，与主站脱节 |
| `src/frontend/js/translate.js` | 另一套前端 | 不属于线上页面 |
| `backend/utils/i18n.py` + `locals/*.json` | 服务端 `t()` | 语言列表不含中文 |

### 1.2 整合结果

- 保留 `translations.js` 的 `window.translations` 结构作为**兼容层**，重写为干净的中英双语包。
- **以 `scripts/i18n.js` 为唯一运行时入口**，重写后包含：
  - 默认语言 `zh-CN`，`document.documentElement.lang = "zh-CN"`；
  - 统一存储键 `agritech_lang`（同时兼容 `lang` / `agritech-lang` / `selectedLang` / Cookie `lang`）；
  - 文本节点 + `placeholder` / `title` / `aria-label` / `alt` 的本地替换；
  - `MutationObserver` 处理 JS 动态插入的文案；
  - 页面右下角「中文 / EN」切换控件，并把原有下拉框统一为「简体中文 / English」；
  - 英文原文保存在 `WeakMap`，可随时切回英文。
- 补充词典分两层：
  1. `scripts/i18n.js` 内置的高频词典（导航、按钮、表单、错误、商城、模型说明等）；
  2. `scripts/locales/zh-CN-extra.js` —— **构建期**用真实浏览器提取未翻译文本、生成离线词典并人工校订农业术语后固化。
- 运行期**不做任何在线翻译**，断网也能显示完整中文。

## 二、货币与计量单位

| 上游 | 本地化 | 换算/处理 |
| --- | --- | --- |
| ₹ / INR | ¥ / CNY | 商城与经营数据按人民币给出；不采用等值换算 |
| `/quintal`（1 公担 = 100 kg） | `/百公斤` | 1 公担 = 100 千克，价格按百公斤计价 |
| `/kg` | `/公斤` | 保持千克 |
| `/liter` | `/升` | 保持升 |
| `acre` | 亩 / 公顷 | 1 英亩 ≈ 6.0703 亩；面积输入统一用亩，产量预测模块保留公顷并单独说明 |
| °F / Fahrenheit | ℃ | 气象与监测统一摄氏度 |
| 面积（ha） | 亩 | 施肥用量：kg/ha ÷ 15 = kg/亩 |

> 说明：印度商品价格不做“卢比等值替换”。商城改为**新编的中国样例价格**并在页面标注「本地演示数据」。
> 保留在页面中的少量卢比样例（历史档案、碳汇等实验页）由运行时换算函数处理，并在文档中说明其性质。

| 位置 | 上游 | 本地化 |

## 四、惠农政策口径

上游政策页写死了 PM-KISAN、PMFBY、KCC、PM-KUSUM 等印度政策、虚构的补贴金额与截止日期。

本地化处理：

1. 保留原页面结构、筛选交互与弹窗。
2. 替换为**中国口径的政策方向**：耕地地力保护补贴、农业保险保费补贴、农机购置与应用补贴、高标准农田建设、绿色种养循环农业试点、农业社会化服务补助、种业振兴与良种推广。
3. **不写金额、不写资格、不写截止日期**；统一标注「需核实资格」「以属地主管部门公告为准」。
4. 链接指向农业农村部、财政部等官方站点（`moa.gov.cn` / `mof.gov.cn`），不指向第三方转载。
5. 政策入口与展示区分：页面只做「方向 → 官方来源」导航，不作申请资格判断。

## 五、气象数据

- 新增 `backend/api/local_core_routes.py` 的 `/api/v1/weather/current`：
  - 优先调用 **Open-Meteo**（免密钥、按省市经纬度），返回真实观测；
  - 网络不可用时返回本地演示气象，并带 `is_demo: true` 与「本地演示天气 · 非实时气象数据」提示；
  - 前端在标题下方显示数据来源与演示标识。
- `weather-banner.js` 移除硬编码的第三方 API Key 与 `New Delhi` 默认值，改走本地接口。
- `weather_dashboard.js` 同步改为本地接口，并补充中文农事建议与演示标识。

## 六、账号与个人信息

| 项目 | 上游 | 本地化 |
| --- | --- | --- |
| 认证后端 | Firebase Auth + Firestore（海外服务） | Flask + SQLite + JWT |
| 邮箱限制 | 仅 `@gmail.com` | 任意常见邮箱，前端与后端规则一致 |

| 角色 | farmer / buyer / equipment / grocery / expert | 保持不变，权限校验不变 |
| 偏好语言 | en / hi / te / ta / mr / gu | zh-CN（默认）/ en |

## 七、AI 服务适配

```
浏览器 ──POST /api/chat──▶ Flask ──▶ AIService
                                     ├─ 有有效 Key：DeepSeek / OpenAI 兼容 /chat/completions
                                     │    └─ 失败 → 明确标注降级
                                     └─ 无 Key / 失败：本地中文规则库
图片 ──base64──▶ 本地 PyTorch 病害模型（自检失败则禁用并说明原因）
```

- 密钥来源：`DEEPSEEK_API_KEY` / `AI_API_KEY`（服务端环境变量），**不下发前端**。
- 系统提示词固定要求：简体中文、可执行农艺建议、不得编造数据、农药需核对登记标签。
- 离线规则库覆盖：水稻、小麦、玉米、番茄、施肥、灌溉、病虫害、行情、账号使用，共 10 类主题；未覆盖时明确说明「知识库没有覆盖这个问题」。
- 图片能力边界：DeepSeek 文本模型不识图，因此图片由本地模型负责；本地模型不可用时**拒绝猜测病害**。
